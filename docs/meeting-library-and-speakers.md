# 회의 목록과 화자 편집

이 문서는 새 Tauri 앱의 소스 계약을 설명한다. 설치 앱, 실제 회의의 정확도와
운영체제별 실기 검증 결과는 별도 확인 대상이다. 기존 Swift 앱의 폴더/화자 구현과
혼용하지 않는다.

## 회의 목록

| 기능 | 현재 동작 |
| --- | --- |
| 생성/수정 | 회의 생성, 제목/메모/회의 날짜 수정. 기본 이름에는 사용 가능한 번호를 붙이며 사용자가 지정한 같은 제목은 허용함 |
| 보기 | 전체 회의, 미분류, 사용자 폴더, 휴지통 |
| 폴더 | 생성/이름 변경/삭제. 중첩 없이 회의당 폴더 하나. 폴더 삭제 시 내용은 미분류로 이동함 |
| 이동 | 개별/일괄 선택과 폴더 드래그 이동. 음성 파일의 실제 경로와 회의 ID는 바꾸지 않음 |
| 삭제 | 휴지통 이동, 복원, 확인 후 영구 삭제 |
| 검색 | 제목, 메모, 음성 기록 본문, 화자 이름, 회의록. 별도 모델을 로딩하지 않음 |

태그, 중첩 폴더와 참석자 그룹은 구현 범위에 포함되지 않는다. 회의 폴더와
참석자 묶음은 서로 다른 개념이다.

검색은 입력 지연과 요청 순서 검사로 이전 검색 결과가 새 검색을 덮지 않게 한다.
회의별 읽기 요청을 나눠 녹음 상태 처리가 중간에 실행될 수 있게 한다. 일부 결과를
읽지 못하면 부분 검색 안내를 표시하며, 읽기 실패를 검색 결과 없음으로 단정하지 않는다.

## 저장과 삭제

- `library.json` 하나가 폴더와 회의의 폴더/휴지통 배치를 소유한다.
  회의 스냅샷의 `folderId`/`deletedAt`은 이 문서의 투영이며 별도 정본이 아니다.
- 라이브러리 변경은 복사본 검증 후 문서 전체를 원자적으로 교체한다. 교체 후
  동기화 실패가 발생해도 실제 저장된 정본에 맞춰 메모리 상태를 다시 반영한다.
- 회의 본문, 원음, 재생 음성, 원시 모델 결과, 수정 기록과 회의록은 회의별 저장소에
  유지한다. 폴더 이동은 이 파일들을 복사하거나 옮기지 않는다.
- 휴지통은 배치 정보만 바꾸며 원음과 결과를 유지한다. 복원은 기존 폴더를 유지하지만,
  그 폴더가 삭제됐다면 미분류로 복원된다. 휴지통에서는 결과를 읽을 수 있고
  새 녹음/변환/요약/본문 수정은 허용하지 않는다.
- 영구 삭제는 휴지통의 회의만 대상으로 한다. 삭제 tombstone을 정본에 먼저 기록해
  목록에서 제외한 뒤 파일을 정리한다. 정리가 중단되거나 실패해도 해당 회의가
  재실행 후 다시 나타나지 않는다. tombstone ID를 새 회의에 재사용하지 않는다.
- 파일 정리 실패는 부분 완료로 표시한다. 앱을 다시 열 때 원음 저장소와 소유 관계가
  확인된 임시 처리 파일의 정리를 재시도하며, 실패가 계속되면 비차단 오류를 표시한다.
  오류 없이 영구 삭제가 완료됐다고 단정하지 않는다.
- 새 처리 작업은 `processing/<job-id>/owner.json`으로 회의 소유권을 기록한다.
  과거 임시 작업은 원시 결과가 한 회의의 보존된 원문과 정확히 일치할 때만 연결한다.
  소유 관계가 없거나 여러 회의와 일치하는 과거 파일은 임의로 지우지 않는다.
  따라서 모든 과거 파생 파일이 제거됐다고 주장할 수 없다. 공유 모델은 삭제 대상이 아니다.

## 작업 중 변경

- 제목/메모/음성 기록의 미저장 수정과 한국어 조합 입력을 저장한 후 목록 변경을 시작한다.
  저장 실패 시 수정 내용을 보존하고 후속 변경을 진행하지 않는다.
- 녹음 중이거나 일시정지한 회의의 삭제는 화면과 Core에서 거부한다.
- 변환/요약 중인 회의를 삭제하면 해당 작업만 취소하고 실제 워커 종료를 기다린 후
  휴지통/영구 삭제를 적용한다. 다른 회의의 작업이나 모델 다운로드를 취소하지 않는다.
- 가져오기 완료 직전에 새 회의가 보이는 경우에도 작업 소유권이 연결될 때까지
  기다린다. 삭제와 새로운 녹음/추론 시작은 같은 처리 경계를 사용한다.
- 저장 단계도 삭제 상태와 회의 존재를 다시 검사한다. 뒤늦게 끝난 변환/요약이나
  오래된 편집 요청이 삭제한 회의를 복원하거나 현재 결과를 덮어쓸 수 없다.
- 휴지통 복원은 취소한 작업을 자동으로 다시 실행하지 않는다. 취소는 원음과
  이미 저장된 결과를 유지한다.

## 화자와 수정 기록

MOSS가 반환한 익명 화자와 사용자가 입력한 이름은 실제 인물의 자동 식별 결과가 아니다.
등록된 목소리 매칭과 독립적인 전체 녹음 화자 분리 모델은 연결되지 않았다.

| 항목 | 현재 계약 |
| --- | --- |
| 자동 표시 | 인식 결과의 화자 ID와 발언별 배정을 보존. 확인할 수 없으면 미지정으로 표시함 |
| 이름 변경 | 해당 회의의 같은 화자 ID에 연결된 이름을 변경함 |
| 배정 수정 | 선택한 발언을 기존 화자/새 화자/미지정으로 변경함 |
| 합치기 | 사용자가 선택한 두 화자를 합치며 발언 배정을 함께 변경함 |
| 취소/되돌리기 | 대화상자 취소는 미저장 수정을 버림. 현재 실행 중 버전이 일치할 때 이전 화자 수정 한 건을 되돌림. 재실행 후 이력 선택 UI는 없음 |
| 충돌 | 읽었던 음성 기록 ID/revision이 달라졌으면 저장을 거부하고 현재 입력을 보존함 |

화자와 본문 수정은 같은 음성 기록 revision을 사용한다. 원음, 원시 결과와 초기
음성 기록은 수정하지 않고 수정본을 별도 보존한다. 화자 이름/배정 변경도 회의록의
입력 변경이므로 이전 회의록은 오래된 결과로 표시한다. 다시 요약할 때 현재 화자
표시와 발언 번호를 전달한다. 복사와 TXT/Markdown 내보내기도 현재 배정을 사용한다.

이전 문서에 화자 필드가 없으면 원시 결과와 구간 시각/원문이 일치할 때만 화자를
복구한다. 이 읽기는 기존 파일, 발언 ID, 사용자의 본문 수정과 revision을 변경하지 않는다.
명시적으로 화자를 지운 수정은 재실행 후 다시 자동 복구하지 않는다. 원문이 없거나
대응이 불확실하면 기존 본문을 읽되 화자는 만들어내지 않는다.

## 모델 구간의 한계

워커는 긴 음성을 나눠 각 구간을 독립적으로 인식한다. 서로 다른 구간의 `S1`은
같은 사람이라는 뜻이 아니다. `asr_chunk`가 있는 결과는
`moss:chunk:<구간 번호>:<모델 라벨>`로 구분하며, 구간 정보가 일부 빠지거나
잘못된 배정은 회의 전체의 동일인으로 추정하지 않는다. 화자 정보를 사용할 수 없어도
유효한 음성 기록 본문은 유지한다.

구간별 화자 항목 수는 실제 참석자 수가 아니다. 같은 사람이 여러 항목으로 나타날 수
있으며, 구간을 가로지르는 동일인 연결은 사용자가 확인해 합치는 단계다. 현재 기능을
회의 전체의 화자 분리/등록 화자 자동 인식이 완료된 상태로 설명하지 않는다.

최대 8명의 실제 화자는 품질 검증 목표이며 검증 완료된 지원 수가 아니다. 참석자가
늘어났다는 이유로 녹음이나 텍스트 변환을 막지 않는다. 실제 회의의 화자 구분,
겹치는 발화와 구간 경계 정확도는 목표 환경에서 별도로 평가해야 한다.

## 확인 범위

| 구분 | 의미 |
| --- | --- |
| 소스/합성 테스트 | 저장/복원, 충돌, 삭제 중 취소와 재생성 방지, 수정 보존, 구간별 라벨 분리 계약 확인 |
| 브라우저 UI | 가상 상태에서 목록/메뉴/대화상자/키보드/좁은 화면을 확인. 실제 파일/마이크/워커 동작의 증거가 아님 |
| 네이티브 앱 | 실제 앱에서 실행한 기능과 결과만 별도 기록. 빌드 성공은 장시간 녹음이나 모델 품질 검증을 대신하지 않음 |
| Windows | 공통 저장/상태와 화면 소스가 대상임. 음성 인식 연결, 설치, 권한, 드라이버와 GPU 실행은 Windows 실기 확인 전 미검증 |

배포/설치 영수증과 개인 회의 기반 평가 자료는 공개 문서에 포함하지 않는다.
